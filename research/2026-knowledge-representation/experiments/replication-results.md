## 3. Parser review and adversarial inputs

All adversarial runs were in the scratch copy using `dotnet fsi`, with the built `Core.dll` and YamlDotNet 18.1.0. A 600,000-call mutation fuzz was run across Yaml, Dsl, Json, Jsonl, YamlText and Markdown readers.

### Yaml.fs: alias and anchor rejection (works)

- Alias or anchor input is rejected: `a: &x [1,2]\nb: *x`, anchor-only, merge-key with alias, alias as a key, and a three-level billion-laughs structure.
- The error is "YAML anchors are not allowed" or "aliases are not allowed", returned before any expansion, so no expansion can occur.
- Tags such as `!!python/object/apply:os.system [ls]` are accepted as inert data, `YSeq ["ls"]`. This is safe because tags are ignored, but they are not rejected as the doc comment ("no tags") implies. Minor documentation mismatch.
- A merge key `<<` parses as an ordinary key when no alias is present. It is safe.
- Complex keys (`? [a,b]`) and multiple documents are rejected with errors.
- `MaxEvents = 20000` is enforced. 25,000 items gave "exceeds event limit", and 20,000 nested `[` was rejected the same way. 9,000 nested flow levels and a sequence of 19,990 items parsed without stack overflow.
- A 50 MB scalar parses. Input size is unbounded at the Yaml level (only event count is limited), which is acceptable for a local tool but is not a resource limit.
- Duplicate mapping keys are silently accepted (`id: A\nid: B` gives two pairs), and `Yaml.field` returns the first. A real YAML 1.2 parser rejects this.

### Issue 1 (real, medium): uncaught exception from Yaml.parse and FrontMatter.split

- `readEvents` catches only `YamlException`. The input `id: [\nb: 1\n` (an unterminated flow sequence followed by a block-style key line) makes YamlDotNet throw `InvalidOperationException`, which propagates out of `Yaml.parse`, `FrontMatter.split`, `Codec.ofYamlText` and `Codec.ofMarkdown`.
- This contradicts the "Never throws" comment on `FrontMatter.split`.
- The fuzz hit it in 465 of 100,000 mutated YAML inputs, and it would also reach `ofMarkdown` (134) and `ofYamlText` (465).
- `Corpus.load` calls `FrontMatter.split` with no `try`, so one hostile file in a corpus aborts the entire benchmark run. The real corpus does not contain such a file.
- Suggested fix: catch `InvalidOperationException` (or all non-fatal exceptions) alongside `YamlException`.

### Issue 2 (real, medium): Dsl.tokenize stack overflow

- Despite "The reader is total: it returns diagnostics", `Dsl.tokenize` is not tail-recursive. The recursive call `go (j + 1) ...` is inside a `try ... with`, which blocks tail-call elimination, so stack depth equals the number of quoted tokens on one line.
- 20,000 quoted tokens on a single line were fine. 100,000 and 300,000 killed the process with `Stack overflow` (uncatchable in .NET). The line is only about 500 KB, far below the 50,000,000-character input bound.
- Bare tokens (300,000 of them) were fine because that branch is a tail call.
- Suggested fix: move the `try` into a helper that returns a Result and keep `go` in tail position, or use an explicit loop.

### Other Dsl.fs behaviour (fine)

- Empty input, garbage, unterminated strings, invalid escapes, NUL and lone surrogates all return `Error` diagnostics with line numbers.
- Unknown fields, including `body` and `id` injection attempts, are rejected rather than accepted. Large inputs were fine: 100,000 records, a 300,000-line body and a 5 MB title.
- The DSL discards unrecognised `Extra` fields on write. It is a lossy format by design (core view), which the docs describe as experimental.

### Codec.fs: YAML block scalars (mostly sound)

Roundtrip tests through `toYamlText` and `ofYamlText`, and through `toMarkdown` and `ofMarkdown`, with these titles and bodies: leading blank line, indented lines, a line with leading space, tabs, `---` and `...` lines, `#` lines, `%YAML` text, emoji and accents, control characters, BOM, trailing newline, a `---` title, a title with `: ` and `#`, and a multi-line title. All roundtripped except the cases below.

- **Issue 3 (low).** A body containing U+2028 or U+0085 breaks the `|2-` block form. YamlDotNet treats those as line breaks, so `ofYamlText` returns "While parsing a block mapping, did not find expected key", which is a clean `Error`. `blockable` should fall back to a quoted string for these characters (and for other C1 and unusual line breaks). The Markdown path is unaffected because the body is outside the front matter.
- **Issue 4 (cosmetic).** Markdown roundtrip trims leading blank lines from the body (`"\nabc"` becomes `"abc"`), and CRLF is normalised to LF. The first is a lossy edge case; the second is expected.
- The `|2-` explicit indentation indicator with `ind = 2*(depth+1)` is correct for top-level maps, which is the only use. I did not test deeper nesting beyond the supported schema.
- `ofYamlText` splits on `(?m)^---\n`. Because block scalar content is always indented, a body line `---` cannot split a document. Confirmed with the `---` body test.

## 4. Overall assessment

- **Reproducibility: good.** All committed outputs regenerate byte-identically except the wall-clock "Compile ms" column. Tests pass 37 of 37. The committed ablation output needs the uncommitted source to be committed.
- **Corpus claims: sound.** 10 of 10 sampled advisory violations are true, 6 of 6 gold sets match hand-derivation including direction semantics, the duplicate-file count (580, and 626 spanning repos) was reproduced independently, and 4 of 4 trial scores re-score exactly.
- **Material error found.** The validation headline of 9 Blocking dangling references is overstated. Eight are one record (praxis EX-ROS-2026-A022) that exists but was dropped by the strict YAML parser, because a plain-scalar title contains `: `. Only 1 is a real missing target. The same silent drop affects DF-ROS-2026-A075, and gold sets and impact analyses involving those records are incomplete. Validation should report front-matter parse failures as their own finding instead of silently excluding the record.
- **Parser safety.** The alias, anchor and event-limit defences work as designed (the billion-laughs input is rejected before expansion). Two "never throws / total" claims are false (issues 1 and 2), both reachable only by deliberately hostile input but both worth a small fix.
- **Evaluation circularity.** Retrieval gold and "compiled" answers both derive from the EKS parser, so those results measure faithfulness of recovery of authored metadata, not independent ground truth. The plain-Markdown comparison condition (0.72 to 0.76) remains the informative contrast.

Counts for sections 2a to 2d: 10 of 10 + 4 of 4 + 6 of 6 + 4 of 4 confirmed (24 checks), plus 1 of 9 blocking confirmed and 8 of 9 refuted as worded, with 0 ambiguous other than the private-name observation.
